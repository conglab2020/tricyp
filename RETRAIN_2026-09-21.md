## The repository already reproduced the retrain, and never reproduced the deployed model

This was worth checking rather than assuming, and the answer is convenient:

- `FocalLoss.forward` computes `((1 - pt) ** gamma * ce_loss).mean()` over
  `F.cross_entropy(..., weight=alpha)`. **At `gamma = 0` the focal term is identically 1**, so the
  criterion is exactly weighted cross-entropy with inverse-frequency class weights.
- The training `DataLoader` uses plain `shuffle=True`. There is **no `WeightedRandomSampler`** and
  no balanced sampling anywhere in `train.py`.

Weighted CE, no balanced sampling, is precisely the September retrain recipe. So the published code
reproduces the **adopted** model with `--focal-gamma 0`, and **cannot** reproduce the previously
deployed model at all, because the balanced sampling that distinguished it was never in this repo.

Changing the default from 2.0 to 0.0 therefore makes the out-of-the-box behaviour match the shipped
weights. It is a one-line change that removes a real reproducibility trap: a user running
`train.py` with the old defaults would have got a third model, matching neither release.

## Verification

All five weight files load under `torch.load` with the architecture `predict.py` expects —
`fc1 (128, 1280)`, `bn1 (128)`, `fc2 (3, 128)`, 164,611 trainable parameters plus batch-norm
buffers. md5s match `models_backup_2026-09-21/retrain_ensemble/` and
`models_backup_2026-09-21/step22/{A..E}/best_model.pth`, which are byte-identical to each other.

End-to-end inference was **not** run: `esm` is not installed in any conda environment on this host,
so `predict.py` cannot execute here. The weights load and the architecture matches; a smoke test on
`example.fasta` should be run wherever the `tricyp` environment lives before publishing.

## Two loose ends

**1. `~/dev/jcys/cys3state` is a stale public duplicate.** It is the pre-rename repository
(`github.com/rschaeff/cys3state`), still carrying the **deployed** weights (md5-confirmed), with an
identical `predict.py`. Its README redirects to `conglab2020/tricyp`, but anyone cloning it gets the
old model with no indication that the thresholds in the paper do not apply. Worth archiving on
GitHub or updating in the same pass.

**2. The README's threshold table is the only place the operating point is written down.**
`predict.py` emits probabilities and applies no threshold, by design. That is defensible, but it
means the 0.696 / 0.788 pair lives only in prose — if it is ever wrong there, nothing in the code
will contradict it.
